# DARTSLIVE HOME BLE実機検証報告（§3）

最終更新: 2026-09-17

## 状態：**ユーザー操作待ち**（指示書§14の明示的な停止条件に該当）

指示書§3は「実機操作が必要」なタスクであり、指示書§14の停止条件
「実機操作が必要」そのものに該当する。加えて、Phase 2投資時点で確認
済みの通り、このセッションが動作するクラウドサンドボックスには
Bluetoothハードウェアが存在せず、また`mcp__remote-devices__device_bash`
（ユーザーPC上でコマンドを実行する手段）は本セッションには提供されて
いない。したがって、実機BLE通信の観測はこのセッションからは技術的に
不可能であり、これまでの調査（`docs/codex/reports/phase2_findings.md`）
の結論から変わっていない。

## 今回実施したこと

「報告して終了」ではなく、指示書§14/§15の「それ以外は、可能な範囲で
継続して実装・テスト・証拠化する」に従い、**ユーザー自身が実施できる
検証手順を自動化するツールを新規作成**した：

1. **`scripts/ble_investigate.py`**：Pythonの`bleak`ライブラリ（BLE用
   クロスプラットフォームライブラリ、Windows/macOS/Linux対応）を使い、
   以下を自動化するスタンドアロンスクリプト：
   - 周辺BLEデバイスのスキャン（10秒間）
   - 選択したデバイスへの接続
   - GATTサービス・characteristic UUIDの列挙、read可能な値の取得
   - notify/indicate可能なcharacteristicへの自動購読
   - 指示書§3が指定する7つの観測タイミング
     （接続直後/投げる前/1投後/3投後/CHANGE後/ラウンド変更時/
     ゲーム終了時）で、ユーザーが実際にその操作を行った直後にEnterを
     押すことでスナップショットを記録する対話型フロー
   - 複数回試行して再現性を確認できるループ
   - 全記録をJSON（構造化）とテキスト（人間可読）の2形式で保存

   **このスクリプトはBLEプロトコルの意味を一切推測・解釈しない**
   （受信したnotifyデータは生のバイト列（hex）としてそのまま記録する
   のみ）。指示書§3の「未公開プロトコルを推測して実装しない」を厳守。

2. **`docs/reports/ble/HOWTO_ja.md`**：上記スクリプトの実行手順を
   日本語で説明（PowerShellコマンド、想定される各段階の結果、
   失敗した場合の対応も含む）。

3. **`docs/reports/ble/investigation_template.md`**：スクリプトを
   使わない場合、または結果を人間の言葉でも整理したい場合の記入用
   テンプレート（指示書§3の分類軸：デバイス非表示/ペアリング不可/
   接続不可/GATT取得不可/データ通知なし/データはあるが意味不明、に
   沿った構成）。

## 依頼事項（ユーザー操作）

1. DARTSLIVE HOME本体の電源を入れ、ペアリング可能な状態にする。
2. `docs/reports/ble/HOWTO_ja.md`の手順に従い、`scripts/ble_investigate.py`
   をご自身のWindows PCで実行する（`pip install bleak`が必要）。
3. 生成された`ble_investigation_*.json`と`.txt`の2ファイルをこの開発
   セッションに送付する。可能であれば、実際にCOUNT-UPを1ゲームプレイ
   しながら7つのタイミングでスクリプトの指示に従って操作していただき
   たい。複数回（2〜3回）試行いただけると、再現性の確認ができる。
4. スクリプトの実行自体が失敗した場合（`bleak`のインストール失敗、
   デバイスが見つからない等）も、その旨と表示されたエラーメッセージを
   教えていただきたい — 失敗の段階自体が指示書§3の求める分類結果として
   有効な報告になる。

## 受領後の対応（次回セッション）

ログファイルを受け取り次第、以下を行う：
- 生データ（GATT UUID構成、notifyのバイト列）を`docs/reports/ble/`配下に
  保存し、実際に観測された事実のみを記録する。
- バイト列の意味の解釈は、複数回の試行データを突き合わせ、明確な
  パターン（例：スコアと相関する位置のバイト値の変化）が見えた場合のみ
  「推定」として明記し、確証が無い部分は「不明」のまま残す
  （指示書§14「外部仕様不明で推測実装になる」場合はさらにユーザー確認
  を挟む）。
- `docs/codex/reports/phase2_findings.md`と本報告書を更新し、
  `UnimplementedBleDartsLiveHomeAdapter`（`src/dartsanalytics/adapters/
  dartslive_home.py`）の実装に着手するかどうかを判断する。

## 結論

実機検証そのものは引き続き未実施（ユーザー操作待ち、指示書§14の停止
条件に該当）。今回、実施のハードルを下げるための自動化スクリプトと
手順書を新規作成し、次にユーザーが行うべき具体的なアクションを明確化
した。
