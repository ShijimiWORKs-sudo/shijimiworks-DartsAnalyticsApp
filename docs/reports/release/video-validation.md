# 動画解析検証報告（§6）

最終更新: 2026-09-17

## 要求事項（指示書§6、原文要約）

基本4方向（正面/利き腕側90度/反対側90度/遠景）それぞれについて撮影条件
（カメラ位置・画角・全身の見え方・足元・ボード・照明・fps等）を明確に
案内する。4動画は同期撮影ではないため正確な同期3D軌道再構成を約束しない。
特徴量を各視点から抽出し、安定した情報を統合する。視認性やconfidenceが
不足した場合は追加動画を要求できる設計にする。

## 現状の実装（Phase 4〜6実装済み部分の監査）

### 撮影条件の案内（`src/dartsanalytics/video/angles.py`）

`ShootingAngle`列挙型で基本4方向＋追加3方向を定義済み：

| 角度 | 用途 |
|---|---|
| `FRONT` | 正面・全身 |
| `DOMINANT_SIDE` | 利き腕側面・全身 |
| `OPPOSITE_SIDE` | 反対側面・全身 |
| `WIDE` | 遠景・投擲位置からボードまで全体 |
| `HAND_CLOSEUP`（追加） | 手元アップ（不足時の追加要求用） |
| `FOOT_CLOSEUP`（追加） | 足元（同上） |
| `DART_FLIGHT`（追加） | ダーツ飛翔（同上） |

各角度の案内文（`GUIDE_TEXT`）は
`docs/specs/DartsAnalyticsApp_スマホ動画撮影手順_v1.0.md`から**逐語転記**
されており、アプリUI文言と仕様書が別々に劣化しない設計になっている
（今回、両者が一致していることを確認した — 転記漏れなし）。

### 撮影品質チェック（`src/dartsanalytics/video/quality.py`）

fps・解像度等の「メタデータ／フレームから実際に判定できる項目」と、
「姿勢推定・物体検出が無いと判定できない項目」を明確に分離している：

**実際に判定される項目（閾値付き）**：
- 解像度: 短辺 ≥1080px、長辺 ≥1920px
- fps: ≥30fps
- 動画長: ≥3秒
- 明るさ: 平均輝度40〜235（範囲外は逆光/暗すぎる or 露出過多）
- シャープネス: Laplacian分散 ≥15（手ブレ/ピンボケ検出）

**「未判定」として明示される項目**（Phase5以降の姿勢推定が必要、
`passed=None`として結果に必ず含まれる — 黙って省略しない設計）：
- `body_fully_visible`（全身が画面内か）
- `limbs_not_occluded`（肘・手首・手が隠れていないか）
- `board_visible`（ボード/スローラインが映っているか）
- `release_visible`（リリース視認性）

→ Phase 5でPose推定が実装済みのため、これら4項目を実際に判定できる状態に
アップグレードすることは技術的に可能だが、**今回はスコープ外**とした
（動画→Pose推定→上記4項目のNG判定への結線は、実際の投球動画での検証
（§4/§6双方が要求する実データ検証）なしに実装すると「未検証のロジックを
検証済みのように見せる」リスクがあるため。既存のPhase 5 notesにも
「実人物映像での検証未実施」と明記されている）。

### 同期撮影ではないことの明示

`video/reshoot.py`のモジュールdocstringに明記の通り、4動画（または7動画）
は**同期撮影を前提としない**設計。単一動画ごとにPose解析
（`pose/analysis.analyze_video_pose`）を独立して実行する構造になっており、
複数動画を時刻同期して3D軌道を再構成するロジックは実装されていない
（意図的— 指示書自身が「約束しない」としている機能）。

### 各視点からの特徴量抽出と統合（今回追加：`src/dartsanalytics/pose/multi_angle.py`）

これまでPose解析（Phase 5）は動画1本単位で完結しており、複数角度の
結果を1セッションとして統合するロジックが存在しなかった。指示書§6の
「特徴量を各視点から抽出し、安定した情報を統合する」を満たすため、
`merge_multi_angle_pose_features()`を新規実装した：

- 各特徴量（body_tilt/shoulder_tilt/hip_tilt/left_elbow_angle/
  right_elbow_angle）について、値を持つ全角度の推定値を集め、
  **confidenceが最も高いものを採用**する。
- **どの角度が「その特徴量に対してより正確か」というバイオメカニクス的な
  優先順位は一切ハードコードしていない**（例：「肘角度は側面からの方が
  正確」等）。そのような主張を裏付ける実測データがこのプロジェクトには
  無いため、design principle「解析不能なものを無理に判定しない」に従い、
  confidenceという既に計算済みの指標のみで判断する。
- 複数角度が同じ特徴量に値を持つ場合、その**差（disagreement_deg）を
  必ず記録**する。平均して差を隠すのではなく、「視点間で値が食い違って
  いる」こと自体を`disagreeing_features()`で明示的に取得できる
  （閾値15度、上書き可能な慣習値 — `board.grouping`の
  `DEFAULT_BULL_VICINITY_RADIUS`と同じパターン）。
- 統合結果のconfidenceは、採用した単一角度の値をそのまま引き継ぐ
  （平均化等で「実際より確信度が高いように見える」統合値を作らない）。

テスト7件で、「単一角度はそのまま通る」「confidenceが高い角度が優先
される」「値が食い違う場合はdisagreement_degに反映される」
「統合値が個々の最良値より高いconfidenceを持つことは絶対にない」ことを
確認済み（`tests/test_pose_multi_angle.py`）。

### 追加動画の要求（`src/dartsanalytics/video/reshoot.py`）

`missing_required_angles`/`recommend_additional_angles`により、4必須角度の
うち未取得・要再撮影のものを判定し、ボーダーライン品質の角度には
関連する追加角度（例：`DOMINANT_SIDE`が悪ければ`HAND_CLOSEUP`）を
提案する仕組みが実装済み（Phase 4）。ただし、このモジュール自身の
docstringに明記の通り、「どの特徴量が不足しているか」の判定はまだ
品質グレード（A/B/C/reshoot）ベースのプレースホルダーであり、Pose解析の
confidence不足を直接のトリガーにする結線は未実装（次の改善候補）。

## 未対応・既知の制約（今回のセッションで新たに確認したもの含む）

1. **実際の投球動画での検証は依然未実施**：Phase 5のnotesで既に指摘されて
   いた通り、実人物のダーツ投球動画は本セッションには一切無い。
   `multi_angle.py`のテストも合成`PoseFeatures`によるロジック検証のみ。
2. **品質チェックの「未判定」4項目とPose解析の結線は未実装**：技術的には
   可能（Phase 5が既にPoseLandmarkerを持つ）だが、実データ無しでの
   実装は「未検証のロジックを検証済みのように見せる」リスクがあるため
   意図的に見送った。
3. **`multi_angle.py`の統合はセッション全体のオーケストレーションに
   まだ組み込まれていない**：`merge_multi_angle_pose_features()`単体は
   実装・テスト済みだが、「1セッションの4本の動画をどのShootingAngleか
   判定し、それぞれをPose解析にかけ、この関数に渡す」という一連の
   パイプライン（Application Service層の仕事）はまだ書かれていない
   （§10で作った`SessionRecordingService`にはまだ動画解析系の
   ユースケースが無い）。
4. **fps条件「等」の「等」が指すその他条件**（手ブレ補正設定、対応
   コーデック等）は、スマホ動画撮影手順書に記載の範囲を超えて検証して
   いない。

## 結論

指示書§6が求める「撮影条件の明確な案内」「非同期撮影である旨の明示」
「視点毎の特徴量抽出」は実装済みであることを確認した。「安定した情報を
統合する」の部分のみ実装が欠けていたため、今回`pose/multi_angle.py`を
新規実装（confidence優先＋不一致の明示、バイオメカニクス的な優先順位の
ハードコードはしない設計）。「追加動画の要求」は品質グレードベースで
実装済み（Pose confidenceベースへの高度化は今後の課題）。303件のテストが
全て合格（新規7件を含む）。
